# Finance and crypto

Written 2026-11-08 from general knowledge, not yet verified against each provider. Bank and exchange security features differ by provider and country, ask the user to read what their provider offers, never assume a feature exists.

## Banks, cards, payment apps, brokers

- Login: the strongest factor the provider offers, its own app or a hardware key, not SMS where an alternative exists. A unique password from the manager.
- A separate email for finance, not the one used publicly or for shopping, so a phishing list or broker profile does not reveal it.
- Alerts on: every login, new device, new payee, card not present payments, transfers above a small amount, address or phone change.
- Limits: daily transfer and card limits set low, raised in the app when needed.
- Cards: virtual or single-use cards for online shopping where offered, freeze toggles known, contactless and online payments limited to what is used.
- New payee and transfer confirmation in the bank's own app, never by a code read out to a caller. A bank never asks for one.
- Devices: banking apps only on the user's own updated phone, not rooted.
- Credit: a credit freeze or fraud alert where the country offers one, much of the EU has no consumer credit freeze, check the credit bureau rules of the user's country, and check reports where the user has the right to see them.
- Accounts no longer used: close them, a dormant account with an old password is an entry point.
- Tax, pension and government portals: they hold identity data, root tier.
- Phone scams: hang up and call the number on the card. Fake bank texts, spoofed caller ID, and deepfaked voices of the bank or relatives are common.

## Crypto, only when the user holds any

Never ask for amounts, coins, addresses or which wallet holds what.

- Custody: long-term holdings in self-custody on a hardware wallet bought from the maker, never second hand, firmware updated from the maker's own app only.
- Seed phrase: written on paper or stamped in metal, stored offline in a place only the user controls, a second copy in a separate place. Never photographed, typed, stored in a password manager, cloud, email, notes, or spoken to anyone. Any request for it is a scam.
- Passphrase on top of the seed for larger holdings, with the trade-off that losing it loses the funds.
- Decoy wallet: a small wallet without the passphrase, for the coercion case.
- Inheritance: a plan someone trusted can follow without the seed being exposed today.
- Exchanges: hardware key as second factor, withdrawal address allowlist with a time lock on new addresses, anti-phishing code, API keys only with the permissions needed and never withdrawal, keep only what is traded.
- Transactions: check the full address on the hardware wallet screen, address poisoning copies the first and last characters. Revoke old token approvals.
- Privacy: never mention holdings publicly or tie an address to the user's name, the targeted and physical risk grows with what is known.
- Scams: fake support in chats, fake airdrops, drainer sites, fake wallet apps, recruitment tests that ask to run code. The browser wallet, if any, gets its own browser profile with no other extensions.

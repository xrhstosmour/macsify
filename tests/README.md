# Tests

Plain `bash` tests, all run by `.github/workflows/lint.yml` next to the `shellcheck`, `fish` and `JSON` checks. Everything else in the repository has no automated test.

- `herdr.sh`: the pinned community mods are never overwritten once installed, the vendored ones are copied again on every run, the replaced `roundup` mods are removed, and a failing check is reported.
- `worktree-cleanup-application.sh`, `tab-names.sh`, `pull-request.sh`, `herdr-application-status.sh` and `herdr-application-resume.sh`: see `.config/herdr-app/README.md`.
- `agentic.sh`: personal skills are removed whatever the line ending, a review script gone from the repository is removed from the installed copy, the old watcher cache is moved once and never over the new one, the `opencode.json` agent models are injected, a plugin enabled by setup keeps the committed ones, and only a committed plugin not installed yet is installed.
- `auto-session-title.sh`: the title hook stops rescanning a transcript whose answer cannot change.
- `bash-output-cap.sh`: the hook rewrites a command without changing its output or exit status, cuts it at the cap, and never rewrites a denied or asked command.
- `webfetch-guard.sh`: the `Claude Code` hook and the `opencode` plugin block the same hosts, userinfo, trailing-dot and non-ASCII forms included, and the plugin caps `bash` output like the hook.
- `claude-settings.sh`: the deny and ask rules in `claude/settings.json` that other setup relies on are still present, it reads the file and does not run the matcher.
- `review-scripts.sh`: the `review-github-prs-watcher` detector reports a requested review, and a pull request reviewed without approving after a push or an answer in a thread of the viewer, never an approved one, once while its review runs and until it is marked done. A dry run claims nothing, it leaves out the merge queue, and rejects a scope with a search qualifier. The poster rejects a bad repository, number, commit, event, comment shape or a body outside a temporary directory and a pull request that moved or is a draft, and posts an `APPROVE` only for a pull request the detector claimed at that commit in the last two hours.
- `review-thread-reply.sh`: `post-thread-reply.sh` replies only to the newest comment of a thread the viewer took part in, written by a person, on an open pull request that is not a draft, to the first comment of the thread.
- `review-worktree.sh`: `review-github-prs-watcher` finds a checkout by its `origin` instead of cloning, puts one detached `reviews` worktree at the pull request head with hooks off, and refuses a moved pull request or a worktree of another repository.
- `green-scripts.sh`: the `green-github-prs-watcher` detector reports your pull request once a member, collaborator or bot commented after you, or once per head for a leftover fixup, a conflict, or a failed check when every check finished, a reason marked done falling through to the next, and caps it after three cycles a day of any reason. The responder reacts, replies, comments, resolves and re-requests reviews only on an open pull request of yours and only for its own comments and threads, replaces the description only through the pull request endpoint, and dispatches a test workflow only at the head it was given and still at it after the checks, never for a fork, a change to `.github` or a workflow that could deploy, itself, through what it calls, or chained on the default branch, unless you trusted that exact tree of the dispatched workflow for that repository with `green-trust.sh`, never a chained one, redone after any file of the tree changes.
- `green-worktree.sh`: one detached `resolves` worktree at the head of your pull request with hooks off, fixups and one-line rewords only of its own commits and changed files, never a submodule or a `.git`, pushes only with a matching lease, commits signed as your git configuration says even from `ccy`, an autosquash that stops on a conflict with the rebase left in progress, a continue that stages exactly the conflicted files with no marker left, an abort that pushes nothing, tests triggered only through a `push` branch pattern the named workflow lists, never one named after a deploy target, only at the pushed head, never next to a deploying workflow or local action the push starts or chains, at the head or on the default branch, unless you trusted that exact tree of the named workflow for the repository of `origin` with the `green-trust.sh` line its exit 5 prints, never a started one, ignores a deploy word in an `if:`, and fails closed on, and never writes, a malformed or linked trust file, never over a tests branch it did not push, or for a pull request that changes `.github`, and a `.git` pointing anywhere else refused before any `git` command runs.
- `green-search.sh`: the green watcher searches only a `resolves` worktree and the `Claude Code` and `OpenCode` sessions of its checkout, takes a pattern and never an option, runs nothing through a `rg` configuration or `~/.sqliterc`, and cuts a long record around the match.
- `repository-sync.sh`: only a clean `main` checkout is rebased, a conflicting rebase is aborted, one whose own configuration or hooks would run a command is skipped.
- `git-editor.sh`: `git/editor.sh` opens `VS Code` only while it runs and its `code` command exists, `hx` otherwise, `vi` without `hx`.
- `profile.sh`: how the work or personal profile is picked and saved, and which Brewfiles it reads.
- `herdr-application-title.sh`: the title hook gives an automatic tab and space the session title, keeps the tab color, never overrides a hand rename, and does nothing outside an app terminal or without a title.
- `herdr-agent-resume-fish.sh`: only the terminal's own `fish` resumes the recorded agent with its flags, a record naming a flag as session resumes nothing, and an agent typed by hand forgets its record when it ends. It needs `fish`.
- `antivirus.sh`: `antivirus/scan.sh` moves an infected file into quarantine with a note and without execute bits, leaves clean files, dependency folders and, with `--recent`, old files alone, and never deletes anything.
- `arrange-displays.sh`: `displays/arrange_displays.sh` runs the compiled placer only when no external keyboard is connected, and does nothing before it is compiled. The placer's geometry is checked by hand.
- `syncthing.sh`: `settings/syncthing.sh` reads the API key and a loopback GUI URL out of `config.xml`, and sends the hardening with the key in a header and the body on standard input.
- `dock.sh`: which `Dock` is Apple's default and where missing applications go. It needs macOS and skips on the `Linux` runner, so run it locally after a `Dock` change.
